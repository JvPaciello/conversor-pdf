## Architecture

**ConverterPDF BR** converts files to PDF entirely in the browser — nothing is uploaded, and there is no backend. All user-facing copy is Brazilian Portuguese.

- Next.js 16 App Router, every route statically prerendered. TypeScript, React 19.
- Tailwind CSS v4. Design tokens are CSS variables in `src/app/globals.css` (`--desk`, `--paper`, `--ink`, `--stamp`…) exposed as Tailwind colors via `@theme inline`; dark mode comes from `prefers-color-scheme`, not a class. Reusable classes there: `.sheet` (paper with folded corner), `.display`/`.heading` (Archivo with the `wdth` axis), `.btn`, `.badge`, `.prose-doc`.
- Path alias `@/*` → `src/*`.

### Layers

- `src/lib/tools.ts` — single source of truth for the three tools: route, accepted formats, page copy (lead, steps, notes, FAQs), metadata. Home, nav, footer, sitemap and tool pages all read from it.
- `src/lib/pdf/` — framework-free PDF generation. Pure modules (`win-ansi`, `image-info`, `page-layout`, `page-cuts`, `sheet-table`, `excel-to-pdf`, `text-to-pdf`) are unit-tested under the Node environment. `docx-to-pdf` and `images-to-pdf` need a real browser (iframe, canvas, `Image`).
- `src/components/converter/` — client components. `useConversion` holds idle/working/done/error state and triggers the download; each converter loads its `lib/pdf` module with dynamic `import()` (and preloads it once a file is chosen) so heavy libraries stay out of the initial bundle.
- `src/components/tool-page.tsx` — shared server layout for the tool routes (breadcrumb, JSON-LD, steps, FAQ).

### Things that are easy to break

- jsPDF's built-in fonts only render WinAnsi (cp1252). Any string passed to `pdf.text`/autotable must go through `toWinAnsi()` or the whole string turns into garbage.
- The Word converter renders inside an off-screen same-origin iframe so Tailwind's preflight can't alter the document; `planPages` moves page breaks to gaps between text lines (atoms come from `Range.getClientRects`). `ignoreLastRenderedPageBreak: false` makes docx-preview follow Word's own pagination.
- `xlsx` is installed from the SheetJS CDN tarball (the npm package is outdated and has advisories). The community build only exposes cell fills, not fonts.
- `public/` must not contain `robots.txt` or `sitemap.xml`; they are generated by `src/app/robots.ts` and `src/app/sitemap.ts`.
- Cookie consent is stored in `localStorage['cookie-consent']` (same key as the previous version of the site).
- The logo's source is `public/logo.svg`. After editing it, run `npm run icons` to regenerate `src/app/favicon.ico`, `icon.png`, `apple-icon.png` and `public/logo.png` (small sizes use a simplified variant).

## Deployment

Vercel, no environment variables. Site URL and AdSense client live in `src/lib/site.ts`; `public/ads.txt` must match the AdSense publisher ID.
